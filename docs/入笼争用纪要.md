# 入笼争用纪要（当日锁死）

> 生效日期：2026-11-22
> 范围：保证金笼母仓 · 同账户并发入笼（`POST /api/cages/freeze`）
> 状态：**已锁死，不得偏离**。偏离本纪要的实现一律记入「入笼争用偏航」并拒写。

## 1. 事故

两名柜员在两个会话中对同一当事人 `party_key` 的可用余额同时点入笼。
旧实现把账户锁 `cage_locks` 的取/放与业务写放在**同一个事务**里：锁行在
`commit` 前对其它连接不可见，应用层互斥在并发下失效；后到者又凭陈旧的
可用余额快照重复整笔入笼。偶发结果：

- 两只笼都建成功（正式笼表 `cages` 多出一只）；
- 账户冻结 `bond_accounts.frozen` 被抬两次；
- 可用余额 `balance - frozen` 被打穿为负；
- 后到者没有任何锁失败痕（`contention_log` 零增、审计无失败事件）。

复现夹具：`tests/conftest.py`（双会话 + WAL + `try_acquire` 双过点门闩）。
失败测：`tests/test_freeze_contention.py`。

## 2. 正确性口径（二选一，全程不得混用）

只允许以下两条路径中的**一条**。本仓当日锁定 **路径甲**，全仓不得出现
路径乙的影子单/晋升表与代码，也不得甲乙混用。

### 路径甲（本仓采用）：账户锁内整笔入笼

1. 入笼先取账户锁 `bond:{party_key}`，**取锁本身独立提交**，锁行在任何
   业务写之前就对全库可见、跨事务持有；
2. 持锁后在**同一提交**内完成：校验账户与可用额 → 插笼 `cages` →
   扣可用/抬冻结 `bond_accounts.frozen` → 写审计 `audit_trail`；
3. 业务提交后再独立提交释放锁；
4. **拿不到锁**：立即 409，正式笼表 `cages`、账户表 `bond_accounts`
   等业务表**零增零改**，只记锁失败痕：
   - `contention_log` 增一条 `争用/锁失败`（含持有者、合约、金额）；
   - `audit_trail` 增一条 `cage_freeze_lock_failed`；
5. 业务校验失败（账户不存在、状态非法、可用不足、笼编码重复）同样不写
   业务表，正常释放本会话持有的锁。

### 路径乙（本仓不采用，仅留档）

先写占位影子入笼单卡住额度，晋升时再原子建笼；占位冲突则后到失败且正式
笼表零增。**本仓禁止落地影子单表、占位状态与晋升流程。**

## 3. 硬约束

- 同账户并发入笼，**只许一人成功建笼**；
- 禁止只改入笼页排队提示等前端文案来冒充互斥（无测改文案一律拒）；
- 五页账实同源：入笼页、账户页、对账页、审计页、增补页读到的笼数、冻结、
  可用、争用、审计必须来自同一套库表与同一套口径，不得各算各的；
- 库路径不改（仍是 `data/app.db`），登录页照旧，不引入新的数据库产品；
- 锁失败痕对两名柜员都可见：后到者会话收到 409，且争用页/审计页可查。

## 4. 偏航处置

任何与本纪要不一致的写法（包括但不限于：锁与业务同事务、影子单、
前端排队替代锁、吞掉锁失败不记痕、冻结与插笼不同提交）均属偏航：

- 在 `contention_log` 记 `入笼争用偏航` 一条；
- 对应写操作拒写（业务表零增）；
- 测试中以 `cage_freeze_deviation_rejected` 断言兜底。

## 5. 验证

- `tests/test_freeze_contention.py` 四条事故测必须绿：
  - 双笼泄漏被钉死（一成一败、笼表零增到一只、冻结只抬一次、可用不打穿、
    后到者留锁失败痕）；
  - 锁失败只记痕（争用 `contention_log` + 审计 `cage_freeze_lock_failed`，
    业务表零增）；
  - 成功与业务校验失败后账户锁都释放、不泄漏、不阻塞后续；
  - 未持锁即整笔写入按「入笼争用偏航」留痕并拒写
    （`cage_freeze_deviation_rejected`）。
- 前两条在旧缺陷代码（锁与业务同事务）上确定性见红，路径甲修复后转绿；
- 既有 `tests/test_smoke.py`、`tests/test_stubs.py` 全绿；
